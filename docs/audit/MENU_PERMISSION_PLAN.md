# 美业 SaaS 菜单角色化方案

> 状态：v0.1 | 2026-08-16 | 待执行

## 一、目标

实现**菜单按角色动态过滤**，底层菜单结构只有一份，用户登录后根据角色自动展示对应菜单。

## 二、现状

### 2.1 菜单结构

- **fallbackMenus**（`Layout.vue`）：12 个一级模块，86 项菜单，hard-coded
- **后端菜单**：`sys_menu_permission` 表通过 `sys_role_permission` + `sys_user_role` 关联用户
- **后端已实现**：`RbacService.buildMenuTree()` 根据用户角色构建菜单树
- **问题**：前端 `Layout.vue` 的 `fallbackMenus` 覆盖了 `store.menus`，后端菜单永远不生效

### 2.2 现有角色

| role_code | 角色名 | 数据范围 |
|---|---|---|
| SUPER_ADMIN | 超级管理员 | ALL |
| STORE_ADMIN | 门店管理员 | STORE |
| EMPLOYEE | 员工 | STORE |
| FINANCE | 财务 | STORE |
| PLATFORM_ADMIN | 平台管理员 | ALL |

### 2.3 路由重复问题

| 路由 A（未挂菜单） | 路由 B（已挂菜单） | 说明 |
|---|---|---|
| `/mkt/promotion` | `/market/activity` | 重复 |
| `/mkt/coupon` | `/market/coupon` | 重复 |
| `/mkt/points` | `/market/points` | 重复 |

### 3.2 技术方案

- **前端**：移除 `Layout.vue` 的 `fallbackMenus`，改为用 `store.menus` 渲染

- **后端**：新增 5 个预置角色 + 菜单权限绑定 SQL
- **路由权限**：`meta.permission` 补全所有路由

### dev/* 路由处理

- 全部标记 `meta.permission: 'dev:access'` 或仅 admin 角色可见
- 不在菜单中暴露（除非管理员手动访问）
