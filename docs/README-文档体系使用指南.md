## 🚀 新项目 5 步上手

### 步骤 1：阅读方法论（30 分钟）

打开 `METHOD-通用项目快速开发方法论.md`，**理解 8 阶段流程**。

```
你要回答的 3 个问题：
1. 我们的项目处于 8 阶段中的哪一阶段？
2. 当前阶段的关键产出物是什么？
3. 下一阶段要做哪些准备？
```

### 步骤 2：复制项目模板（2 分钟）

```
复制：MODULE-TEMPLATE-项目模块开发验证体系模板.md
重命名为：MODULE-[你的项目名].md
```

### 步骤 3：替换占位符（10 分钟）

在复制的 `MODULE-[你的项目名].md` 中，**全局替换占位符**：

| 占位符 | 替换为 | 示例 |
|---|---|---|
| `[项目名]` | 你的项目中文名 | 电商系统 |
| `[项目代号]` | 项目英文代号 | mall |
| `[公司英文名]` | 公司英文名 | qiaopm |
| `[项目前缀_]` | 数据库表前缀 | mall_ |
| `[8080]` | 后端端口 | 8080 |
| `[前端端口]` | 前端端口 | 5173 |
| `[MySQL 密码]` | 数据库密码 | your_password |
| `[公司包名]` | Java 包名 | com.qiaopm.mall |

**快速验证**：搜索 `[` 看是否还有未替换的占位符。

### 步骤 4：填写项目信息（30 分钟）

在 `MODULE-[你的项目名].md` 的 **"二、项目信息"** 和 **"三、模块清单"** 章节填写：

```
[ 项目基本信息 ]  → 项目代号、类型、目标用户
[ 技术栈 ]         → 与模板默认一致则无需修改
[ 命名规范 ]       → 表前缀、包名
[ 模块清单 ]       → M01 ~ Mxx 你要做哪些模块
```

### 步骤 5：按"执行清单"推进（项目周期）

按 `MODULE-[你的项目名].md` 的 **"十、执行清单"** 推进：

```
第一阶段：环境搭建（2-4 小时）
   ↓
第二阶段：项目初始化（1-2 小时）
   ↓
第三阶段：模块开发（每个 3-5 天，按模块清单逐个推进）
   ↓
第四阶段：联调与上线
```

**每个 Mxx 模块完成时**，复制 `MODULE-[你的项目名].md` 的 **"五、模块任务清单模板"** 作为该模块的独立章节追加到文档中。

## 📖 不同角色怎么读

### 我是新来的开发者（最常见）

1. 先读 `README-文档体系使用指南.md`（本文）
2. 再读 `METHOD-通用项目快速开发方法论.md`（理解方法论）
3. 看 `MODULE-模块化开发验证体系.md`（美业实例）**第七节**了解初始化过程
4. 找你当前负责的 Mxx 模块，复制 `MODULE-TEMPLATE` 的"五、模块任务清单模板"开始开发

### 我是新项目的负责人

1. 读 `METHOD-通用项目快速开发方法论.md` 顶层 8 阶段
2. 复制 `MODULE-TEMPLATE-项目模块开发验证体系模板.md`
3. 按"上手 5 步骤"逐步推进
4. 维护本项目独立的 `MODULE-[你的项目名].md`

### 我是产品经理 / 业务方

1. 读 `METHOD-通用项目快速开发方法论.md` 的 **Phase 1-2**（需求阶段）
2. 参考 `PRD-美业SaaS系统功能大全.md` 了解 PRD 模板（如果有）
3. 配合 Module Owner 填写 Mxx 的"模块功能清单"

### 我是技术负责人 / 架构师

1. 读 `METHOD-通用项目快速开发方法论.md` 全文，关注 8 阶段质量门禁
2. 维护 `MODULE-TEMPLATE-项目模块开发验证体系模板.md`（确保模板与时俱进）
3. 评审各项目的 `MODULE-[项目名].md`

## 🔄 文档更新机制

### 哪些文档需要更新

| 文档 | 更新频率 | 谁负责 |
|------|---------|--------|
| `METHOD-...方法论.md` | 季度/半年（方法论升级） | 架构师 |
| `MODULE-TEMPLATE-...模板.md` | 半年（通用部分优化） | 架构师 |
| `MODULE-[项目名].md` | 每个模块完成时 | 项目负责人 |
| `PRD-...` | 需求变更时 | 产品经理 |
| `TECH-...` | 技术栈变更时 | 技术负责人 |
| `TEST-...测试报告.md` | 每个模块完成时 | QA / 项目负责人 |

### 如何反馈问题

发现模板 / 方法论有问题时：
1. 在 `MODULE-TEMPLATE-...` 末尾的"文档维护日志"追加 issue
2. 抽时间集中讨论，统一更新
3. 重大变更要在 `README` 顶部说明

## 🎯 体系核心价值

```
为什么需要这套文档体系？

❌ 没有文档：
   每个新项目从 0 写文档 → 重复造轮子 → 风格不统一 → 团队协作低效

✅ 有了文档体系：
   - 新项目 = 复制模板 + 改占位符 + 填项目信息（30 分钟）
   - 方法论 = 通用经验沉淀（一次写好，永久复用）
   - 实   例 = 真实项目参考（举一反三）
   - 跨项目 = 统一技术栈 / 流程 / 规范（团队战斗力提升）
```

## 💡 进阶建议

### 当你做了 3 个不同类型项目后

回顾 `MODULE-TEMPLATE-...` 是否还需要扩展：
- 如果发现不同项目类型差异大 → 考虑拆分多个类型模板（CRM / 电商 / 教育）
- 如果发现通用部分已经够用 → 继续保持单一模板

### 当你想把这套体系"对外输出"时

- 把 `METHOD-...` 整理为博客 / 培训材料
- 把 `MODULE-TEMPLATE-...` 整理为开源项目模板
- 这个 README 作为体系说明
