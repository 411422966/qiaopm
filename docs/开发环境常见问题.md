# 开发环境常见问题

本文档记录 QiaoPM 项目在本地开发过程中遇到的各类非业务代码错误的排查记录，便于团队成员快速定位问题。

---

## 1. 控制台报错 "Could not establish connection. Receiving end does not exist."

### 错误现象

在浏览器 DevTools Console 中出现以下错误：

```
Uncaught (in promise) Error: Could not establish connection. Receiving end does not exist.
```

错误源指向 `consent:1`（或任意页面 `:1`），**非任何 `.vue` / `.js` 业务文件**。

### 原因

**浏览器扩展的 Content Script** 在页面加载时尝试与扩展的 background script / popup 建立通信通道（通过 `chrome.runtime.connect` 或 `chrome.runtime.sendMessage`），但 background 端尚未就绪或已被卸载。

常见触发扩展：
- Vue DevTools / React DevTools
- MetaMask 及各类钱包扩展
- Tampermonkey / Violentmonkey 用户脚本
- 广告拦截器（uBlock Origin、AdGuard 等）
- 翻译类扩展（Google Translate、DeepL Helper 等）

### 排查结论

项目源码中**没有任何** `chrome.` / `browser.` / `runtime.sendMessage` / `tabs.sendMessage` / `runtime.connect` / `postMessage` 调用，排除业务代码嫌疑。

### 解决方案（三选一）

#### 方案 A：DevTools Console 过滤器（临时屏蔽，推荐）

1. 打开任意报错的页面
2. F12 → Console（控制台）
3. 顶部 Filter 输入框输入：

   ```
   -Could not establish connection
   ```

   减号前缀表示隐藏包含该文字的消息。
4. 按 Enter 即可。**刷新页面后过滤仍然生效**，直到手动清除。

#### 方案 B：隐身窗口验证（最彻底）

1. Chrome → 右上角三个点 → **新建隐身窗口**
2. 访问 `http://localhost:5173/<对应页面>`
3. 隐身窗口默认不加载用户安装的扩展（除非手动开启）
4. 如果控制台**完全干净**，即可确认是扩展导致，与项目无关，无需任何代码改动。

#### 方案 C：逐个禁用扩展定位元凶（二分法）

1. 地址栏右侧点击扩展图标（🧩拼图）→ 逐一禁用可疑扩展
2. 每禁用一个，刷新页面一次，观察报错是否消失
3. 二分法：一次禁用一半 → 缩小范围 → 重复，**最多 log₂(N) 次**即可定位（假设有 N 个可疑扩展）

### Vite 开发服务器能否过滤此类错误？

**无法做到。** 原因如下：

1. `Could not establish connection` 是浏览器扩展注入到页面 DOM/JS 上下文的错误，Vite 作为前端构建工具和开发服务器，它**看不到也管不了**浏览器扩展的代码执行。
2. Vite 的日志级别配置（`server.logLevel`）仅控制 Vite 自己输出的 HMR 连接信息、编译错误等，无法过滤来自 extension context 的 console 报错。
3. 唯一能在浏览器端做全局过滤的方式是**安装浏览器扩展本身**（如 "Console Filter" 扩展），但这不是项目代码应该承担的职责。

因此，对于此类错误，**推荐使用方案 A（DevTools 过滤器）** 在开发时保持控制台整洁，或使用方案 B 做一次性验证。
