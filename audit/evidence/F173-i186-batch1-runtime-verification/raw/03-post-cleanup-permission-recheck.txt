§4. ITEM5 误判复刻（raw/02-item5-recheck.txt 的脚本盲区）
--------------------------------------------------------------------------------
【脚本盲区】raw/recheck-item5.ps1 的 GetJson 函数在 catch 分支里**丢弃了 HTTP 状态码**：

    function GetJson($path, $tok) {
        try {
            $r = Invoke-RestMethod -Uri "$base$path" -Headers @{Authorization="Bearer $tok"} -Method Get
            return @{ ok=$true; http=200; data=$r.data }
        } catch {
            return @{ ok=$false; http=-1; data=$null }     # <-- 403 与 404/500 全部塌缩成 http=-1
        }
    }

  Invoke-RestMethod 对 HTTP 403 抛异常 -> catch -> data=$null。
  于是 `records.count` 被判为 0、`statistics.totalRecords` 被判为 $null，
  脚本再据此写出 "DEFECT_CONFIRMED（缺省日期时 statistics 恒 0，records 非 0）"。

【按同一取数逻辑复刻，逐字对齐脚本输出】
  脚本视角                          真实 HTTP
  ---------------------------------------------------------------------------
  records.count=0                   403  "权限不足: 需要权限码：attendance:list"
  statistics.totalRecords=(空)      403  "权限不足: 需要权限码：attendance:stat"
  判定 DEFECT_CONFIRMED            <-- 事实为「权限不足」，非「统计恒 0」

【结论】raw/02-item5-recheck.txt 的 DEFECT_CONFIRMED **不成立**，属于脚本缺陷导致的假阳性。
          该文件本身**不构成独立证据**（其结论方向与事实相反）。

【与首轮运行的对照】首轮运行（11-17 23:21）确实记录到 ITEM5 FAIL
（records=1 / statistics.totalRecords=0），主验证脚本本身**记录了 http=403 与响应体**，
两个端点的真实状态码在主验证文件内可核（raw/01 V13 一行给出 records 与 statistics 的数值），
但主验证**未记录这两个端点各自的 HTTP 状态码**——这是主验证脚本的第二处盲区，
只能由本次复检补上。

§7. 结论
--------------------------------------------------------------------------------
  1) F173 主验证（2026-11-17 23:20 - 23:33）取得的 PASS **是在 11-16 23:34:53 的临时授权
     窗口内**取得的；该临时授权已于 11-17 23:36:34 被单事务撤销。

  2) 撤销之后，**同一账号（manager01）、同一端点**的 HTTP 状态码发生 11 处状态翻转
     （200 -> 403，403 原因全部为「权限不足：需要权限码：X」），其余项状态不变
     （本就已经是 403 的越权项）或因夹具清理数据量下降。
     => **主验证 PASS 在清理后不可复现**。

  3) 依赖已删除夹具账号的主验证 V9 / V10 / V11、补测 2、补测 3 **本轮无法复跑**，
     其 PASS 同样无法在当前基线上复现。

  4) raw/02-item5-recheck.txt 的 "DEFECT_CONFIRMED" 为**脚本盲区导致的误判**，
     真实原因是 403 权限不足，非统计口径缺陷。

  5) **F173 主验证 PASS 依赖临时授权，清理后不可复现，不能单独作为 I186 验收证据。**
     I186 第 1 批的运行期结论必须在**基线授权状态**（补齐 I183 / I184 的权限码绑定）
     之下重跑，才能作为验收证据。

  6) 本文件为**只读复检**证据：未修改任何业务代码、未写库、未做 DDL、未动任何部署产物。
